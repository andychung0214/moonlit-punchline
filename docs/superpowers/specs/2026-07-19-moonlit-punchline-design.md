# Moonlit Punchline／月下冷梗旅店設計規格

## 1. 產品定位

- 英文專案名稱：Moonlit Punchline
- 中文名稱：月下冷梗旅店
- 專案目錄：`moonlit-punchline`
- 類型：蒐藏型冷笑話問答遊戲
- 平台：桌機瀏覽器優先，支援平板與行動觸控
- 首版形式：可部署至任何靜態網站託管環境的單頁網站
- 內容尺度：全齡友善，適合親子、校園與辦公室
- 語言策略：繁體中文為主；跨文化題目保留來源地區與繁中註解

產品以「深夜旅店收集世界冷梗」為主題，讓訪客既能進行有目標的問答挑戰，也能像翻閱收藏冊般自由欣賞冷笑話。首版避免帳號、後端與外部服務，確保下載後即可執行。

## 2. 目標與成功條件

### 2.1 產品目標

1. 提供 72 題經過校對的全齡冷笑話、文字梗與創意諧音。
2. 以兩種互補模式兼顧遊戲性與輕鬆閱讀。
3. 讓訪客理解跨文化笑點，而非僅看到翻譯後失去脈絡的句子。
4. 在不登入、不連接後端的前提下保存分數、收藏與偏好。
5. 以具有人味的日式侘寂視覺降低制式 AI 產物感。

### 2.2 首版成功條件

- 使用者可從首頁在三次操作內開始任一模式。
- 四選一挑戰每局抽出 10 題且同一局不重複。
- 作答後立即顯示正確答案、笑點說明與來源地區。
- 放映室可依六類篩選、翻牌、收藏、複製分享文字與切換題目。
- 重新整理後可保留最佳分數、收藏、已看題目與音效偏好。
- 鍵盤可完成所有主要操作，互動目標在手機上不小於 44 × 44 CSS px。
- 偏好減少動態效果的使用者不會看到非必要動畫。
- 自動測試通過，並完成桌機、手機、鍵盤與靜態伺服器手動驗證。

## 3. 範圍

### 3.1 首版包含

- 旅店大廳首頁
- 四選一挑戰模式
- 冷笑話放映室
- 六類、每類 12 題，共 72 題
- 題目分類、難度、來源地區與文化／語言註解
- 最佳分數、收藏、已看題目與偏好儲存
- Web Audio API 程式化音效與靜音控制
- Clipboard API 複製分享文字與降級處理
- 三組 RWD 版面
- SEO Meta Tag、Open Graph、結構化資料、`sitemap.xml` 與 `robots.txt`
- Node 內建測試與瀏覽器手動測試頁

### 3.2 首版不包含

- 帳號、登入或雲端同步
- 使用者投稿與內容審核後台
- 真正的多人排行榜或即時對戰
- 後端服務、資料庫、外部分析追蹤
- 第三方框架、套件管理器必要相依或遠端字型
- 產生或轉傳梗圖圖片

## 4. 內容設計

### 4.1 題庫分類

| 分類 ID | 顯示名稱 | 題數 | 內容原則 |
|---|---|---:|---|
| `zh-pun` | 華語諧音 | 12 | 繁中讀音或字形可理解 |
| `wordplay` | 文字遊戲 | 12 | 雙關、拆字、慣用語轉折 |
| `nature` | 動植物冷知笑 | 12 | 動物、植物與自然題材 |
| `daily-life` | 食物與日常 | 12 | 家庭、校園、工作與飲食 |
| `world` | 世界冷梗 | 12 | 翻譯後仍成立並附來源註解 |
| `absurd` | 荒謬邏輯 | 12 | 反預期、字面化與無害荒謬 |

### 4.2 題目資料契約

每題是不可變的 JavaScript 物件，包含：

- `id: string`：全域唯一且穩定，例如 `zh-pun-001`
- `category: string`：六種分類 ID 之一
- `question: string`：題幹
- `answer: string`：唯一正確答案
- `distractors: string[]`：恰好三個互不重複的干擾選項
- `region: string`：來源地區或「跨文化」
- `note: string`：一句笑點、文化或語言說明
- `difficulty: 1 | 2 | 3`：難度

載入時驗證必填欄位、ID 唯一性、分類、難度、干擾選項數量與答案是否重複。題目不得包含髒話、成人暗示、仇恨、歧視、身體羞辱或針對弱勢身分的笑點。

## 5. 資訊架構與遊戲流程

### 5.1 旅店大廳

首頁展示中文名稱、簡短世界觀、今日冷度、最佳連勝與收藏數。兩張主要模式入口以障子門呈現：

1. 「入住挑戰房」進入四選一挑戰。
2. 「走進放映室」進入自由瀏覽。

次要操作包含音效切換、玩法說明、題庫分類概覽與清除本機紀錄。

### 5.2 四選一挑戰

1. 從 72 題隨機抽出 10 題，同一局不重複。
2. 每題將正確答案與三個干擾選項洗牌。
3. 選擇後鎖定選項，立即標示正確答案。
4. 答對增加 100 基礎分；連勝額外增加 `min(streak, 5) × 20` 分。
5. 答錯不扣分、不扣生命，連勝歸零。
6. 顯示答案、註解、地區與「下一題」。
7. 第 10 題後顯示總分、答對數、最高連勝、收藏操作與重新挑戰。

遊戲不設強制倒數，讓閱讀與無障礙操作不受時間壓力。視覺可顯示「體感冷度」，但不影響計分。

### 5.3 冷笑話放映室

放映室預設從全部題目中選擇一題，使用者可：

- 依六類或全部篩選
- 點擊或按鍵翻牌揭曉答案
- 查看笑點註解與來源地區
- 收藏／取消收藏
- 複製「問題＋答案＋網站名稱」分享文字
- 切換上一題、下一題或隨機一題
- 選擇只看收藏

篩選結果為空時顯示友善空狀態與返回全部題目的按鈕。

## 6. 視覺方向

### 6.1 核心風格

採「月下冷泉旅店」方向：和紙質地、冬夜留白、低飽和藍綠與月光色。幽默來自過度認真記錄冷度的旅店標示、房牌與印章，而非大量卡通素材。

### 6.2 色票

| Token | 色彩 | 用途 |
|---|---|---|
| `--color-paper` | `#F3F0E8` | 頁面主背景 |
| `--color-ink` | `#17343B` | 主要文字 |
| `--color-night` | `#102A35` | 深色區塊與頁尾 |
| `--color-spring` | `#557F78` | 主要操作與分類 |
| `--color-moon` | `#E5C36A` | 焦點、分數與小面積強調 |
| `--color-stamp` | `#9E4B50` | 答對、印章與警示 |
| `--color-mist` | `#DCE7E3` | 卡片與次要背景 |

所有文字與背景組合需符合 WCAG 2.1 AA 一般文字至少 4.5:1 的對比需求。

### 6.3 字體策略

不下載遠端字型。無襯線字型堆疊為 `"Noto Sans TC", "Yu Gothic", "Hiragino Sans", "Microsoft JhengHei", sans-serif`；題目可使用系統明體堆疊增加旅店文書感，但不得犧牲小螢幕可讀性。

### 6.4 元件語彙

- 房牌：分類籤與模式名稱
- 障子門：首頁模式入口
- 湯牌：分數、連勝、進度
- 酒紅印章：答對與收藏完成回饋
- 月相圓形：題目進度
- 紙張卡片：問題與答案，不使用玻璃擬態

### 6.5 動畫與音效

- 動畫時間介於 160–420ms。
- 使用淡入、紙張翻面、印章落下與輕微霧氣位移。
- 答錯只降低色溫，不使用劇烈晃動或閃爍。
- `prefers-reduced-motion: reduce` 時停用翻面、印章與霧氣動畫。
- 音效預設關閉；使用者開啟後才建立 AudioContext。
- 答對為短風鈴、答錯為低沉冷風、翻牌為輕木魚聲。

### 6.6 禁止事項

- 不使用紫藍霓虹漸層、玻璃卡片或發光描邊。
- 不使用無意義的 3D 漂浮物與制式 AI 人物插圖。
- 不用動畫延遲必要資訊或阻擋操作。
- 不只靠顏色傳達答對、答錯或焦點狀態。
- 不使用未確認授權的圖片、字型或音效檔案。

## 7. RWD 與無障礙

- 手機：`0–639px`，單欄、底部友善操作、觸控目標至少 44 × 44 CSS px。
- 平板：`640–1023px`，雙欄入口與較寬答題卡。
- 桌機：`1024px` 以上，以橫向旅店大廳構圖，內容最大寬度 1200px。
- 使用語意化標題、按鈕、導覽與區段。
- 所有互動可用鍵盤操作，焦點樣式清楚可見。
- 作答結果與複製結果透過 `aria-live` 宣告。
- 翻牌元件維持正確閱讀順序，不以純 CSS 視覺順序取代 DOM 順序。
- 裝飾圖形設為對輔助科技隱藏。

## 8. 技術架構

### 8.1 技術限制

只使用 HTML、CSS 與 Vanilla JavaScript。可使用 Canvas、Web Audio API、`localStorage` 與原生 ES Modules；不得使用 React、Angular、Vue、TypeScript、後端服務或大型遊戲引擎。

### 8.2 檔案責任

- `index.html`：語意頁面骨架、SEO 與應用程式掛載點
- `styles/tokens.css`：色彩、字體、間距與陰影變數
- `styles/base.css`：重設、排版與無障礙基礎
- `styles/components.css`：按鈕、卡片、房牌、狀態與對話框
- `styles/layout.css`：大廳、模式畫面與三組 RWD
- `styles/motion.css`：動畫及減少動態效果規則
- `data/jokes.js`：72 題與分類中繼資料
- `scripts/joke-engine.js`：題庫驗證、抽題與選項洗牌純函式
- `scripts/game-state.js`：初始狀態、作答與計分純函式
- `scripts/storage.js`：本機儲存、資料清理與記憶體降級
- `scripts/audio.js`：Web Audio API 音效與支援檢測
- `scripts/share.js`：分享文字與 Clipboard API 降級
- `scripts/ui.js`：DOM 轉譯、事件繫結與焦點管理
- `scripts/app.js`：應用程式啟動與模組協調
- `tests/*.test.js`：Node 內建自動測試
- `tests/browser-test.html`：瀏覽器手動互動測試

### 8.3 資料流

資料流保持單向：

```text
使用者操作 → 事件處理 → 純函式產生新狀態 → 必要時儲存 → DOM 重新轉譯 → 焦點／ARIA 回饋
```

題庫資料不在執行期間修改。UI 不直接計算分數或操作儲存格式；它只呼叫各模組公開函式。

## 9. 錯誤與降級策略

- 題庫驗證失敗：開發測試直接失敗；正式畫面顯示無法載入題庫的錯誤區塊，不開始不完整遊戲。
- `localStorage` 不可用、額度不足或內容損壞：清理不合法資料並改用記憶體模式，顯示非阻斷提示。
- Web Audio API 不支援：隱藏音效切換，不影響遊戲。
- Clipboard API 不支援或被拒絕：將分享文字顯示在可選取欄位並自動選取。
- JavaScript 模組載入失敗：`noscript` 與靜態錯誤文案說明需啟用 JavaScript。
- 分類無題目：顯示空狀態並提供回到全部題目操作。

## 10. 測試策略

### 10.1 自動測試

使用 Node 內建 `node:test` 與 `node:assert/strict`，不依賴大型測試框架：

- 驗證 72 題、六類各 12 題與資料契約
- 驗證 ID、選項與題目內容不重複
- 驗證抽取 10 題且無重複
- 驗證選項洗牌保留唯一正解
- 驗證計分、連勝、答錯歸零與結算
- 驗證收藏切換與序列化
- 驗證損壞儲存資料及儲存失敗時降級
- 驗證分享文字格式

### 10.2 手動與瀏覽器測試

- 桌機 Chrome／Edge 完整兩種模式
- 360px 手機與 768px 平板版面
- 觸控操作與 44px 目標尺寸
- 只用鍵盤完成開始、作答、翻牌、收藏與返回
- 螢幕閱讀器可得知題號、結果與複製狀態
- `prefers-reduced-motion` 下無非必要動畫
- 音效預設關閉，開啟後可播放並保存偏好
- 重新整理後分數與收藏仍在
- `localStorage` 被停用時遊戲仍可繼續
- 靜態伺服器根路徑與子路徑均能載入相對資源

## 11. SEO 與靜態部署

- 提供繁中標題、描述、Canonical、Open Graph 與 Twitter Card Meta Tag。
- 以 `WebApplication` 結構化資料描述遊戲；題庫不為每題建立獨立網址。
- 所有資源使用相對路徑，支援一般靜態網站與 Synology NAS Web Station 子目錄部署。
- 提供 `robots.txt` 與 `sitemap.xml`；正式網址在部署時由文件說明替換。
- 不引入需要建構步驟的依賴；可直接開啟首頁，但 ES Modules 的完整相容執行與測試建議使用本機靜態伺服器。

## 12. 里程碑與驗收

1. **專案基礎與文件**：文件、授權、貢獻規範、SEO 骨架與測試指令齊備。
2. **題庫與遊戲核心**：72 題通過契約測試，抽題、洗牌、計分與儲存純函式通過測試。
3. **旅店大廳與挑戰模式**：桌機與鍵盤可完成 10 題並正確結算。
4. **放映室與裝置能力**：篩選、翻牌、收藏、複製與音效降級可用。
5. **視覺、RWD 與無障礙**：三組斷點、減少動態效果與對比檢查完成。
6. **發布驗證**：所有自動測試與手動清單通過，可由靜態伺服器執行。

每個里程碑完成後必須執行對應自動測試或瀏覽器實測並保留結果；未驗證的功能不得宣稱完成。

## 13. 風險與緩解

| 風險 | 影響 | 緩解方式 |
|---|---|---|
| 跨文化笑話翻譯後失去笑點 | 題目令人困惑 | 只收錄繁中仍成立者並提供註解 |
| 72 題內容品質不一致 | 重玩性下降 | 契約測試、分類校對與全齡內容檢查 |
| 干擾選項太明顯 | 挑戰性不足 | 同類語意、相近長度與避免格式洩漏 |
| 瀏覽器儲存或剪貼簿權限受限 | 功能部分失效 | 記憶體模式與手動複製降級 |
| 音效造成打擾 | 使用者離開 | 預設關閉、短音效、可永久靜音 |
| 靜態子路徑部署資源失效 | 正式站無法載入 | 全部使用相對路徑並測試子路徑 |
